
# Mirevox Smart Router — Functional & Non-Functional Requirements (v0.1 FR/NFR)

- **Brand / Repo:** Mirevox (`https://github.com/Mirevox/smart-router`)
- **Version:** `0.1.0` (Runnable Stub Gateway)
- **License:** Apache-2.0
- **Scope Lock:** All `v0.1` requirements below are locked to the shipped Hono/TypeScript implementation. Every requirement has a measurable exit condition and a concrete verification method. Unimplemented hardening items are segregated into Section 3 (`v0.2` Deferred Gates) so no v0.1 gate relies on vapor.

---

## 1. Functional Requirements (v0.1 Locked)

| ID | Category | Mode | Requirement Statement | Measurable Exit Criterion | Verification Method |
| --- | --- | --- | --- | --- | --- |
| **`FR-01`** | Gateway — Chat Completions | Stub backend / Live contract | `POST /v1/chat/completions` accepts `{ model, messages, temperature?, stream?, max_tokens?, activity?, placement?, backend? }`, evaluates routing policy, and returns an OpenAI-shaped `chat.completion` JSON body containing a `mirevox` routing block. | HTTP `200`; response contains `id` matching `/^chatcmpl_[0-9a-f]{24}$/`, `object === "chat.completion"`, `created > 0`, `model === req.model`, `choices[0].message.role === "assistant"`, `choices[0].message.content` containing `[mirevox-stub/<backend>]` and user prompt echo (up to 500 chars), `choices[0].finish_reason === "stop"`, `usage.total_tokens === usage.prompt_tokens + usage.completion_tokens`, and `mirevox.{backend, placement, activity, stub: true}`. | `test/gateway.test.ts` + `curl` smoke check |
| **`FR-02`** | Gateway — Request Validation & Streaming Guard | Live | `POST /v1/chat/completions` rejects invalid requests and explicitly refuses unsupported streaming. | Missing `model` or non-array `messages` returns HTTP `400` with `{"error":{"message":"model and messages are required","type":"invalid_request_error"}}`. `stream: true` returns HTTP `501` with `{"error":{"message":"streaming not implemented in v0.1 stub","type":"invalid_request_error"}}`. | Integration request tests against `createGateway()` |
| **`FR-03`** | Gateway — Model Catalog | Stub data / Live endpoint | `GET /v1/models` returns all models exposed by currently enabled providers in `DiscoveryRegistry` in OpenAI list format. | HTTP `200`; `object === "list"`; `Array.isArray(data)` with `data.length === 14` under `config/default.yaml` (2 models x 7 enabled providers); every item contains `id`, `object: "model"`, `created`, `owned_by`, `backend`, `placement` (`"onprem"` for `local`/`mcp`, `"cloud"` otherwise), and `stub: true`. | `test/gateway.test.ts` ("lists models") |
| **`FR-04`** | Gateway — Authentication & Error Envelope | Live | All routes except `GET /` and `GET /health` enforce `Authorization: Bearer <gateway.api_key>` when `gateway.api_key` is non-empty; empty `gateway.api_key` permits open local-dev access. All `HTTPException` errors and uncaught failures return a uniform JSON envelope. | Missing or mismatched Bearer token returns HTTP `401` with `{ error: { message: "Invalid API key", type: "invalid_request_error" } }`. Uncaught runtime errors return HTTP `500` with `{ error: { message: "internal_error", type: "server_error" } }`. `GET /` and `GET /health` return `200` with no `Authorization` header. | `test/gateway.test.ts` ("rejects missing api key") + unauthenticated `/health` probe |
| **`FR-05`** | Routing — Placement & Backend Policy | Live | `RoutingPolicy.decide()` resolves `placement` (`override` > `routing.activities[activity]` > `routing.default_placement`, defaulting omitted `activity` to `"chat"`) and `backend` (`override` > prefix-glob `routing.model_routes` > `routing.fallback_backend`). When `placement === "onprem"`, `activity === "code"`, no `backend` override is provided, and an unprefixed model hits `fallback_backend`, it redirects to the first enabled `local` provider. | 5/5 policy unit tests pass: `gpt-4o-mini` (`chat`) -> `mock-openai`/`cloud`; `local/llama3.2` (`code`) -> `local-ollama`/`onprem`; `foundry/gpt-4o` -> `azure-foundry`; explicit `placement` override honored; explicit `backend` override honored. `GET /admin/routes` returns `200` with `{ routing, sample }` (length 3). | `test/policy.test.ts` + `GET /admin/routes` |
| **`FR-06`** | Fan-Out — Parallel Task Execution | Live orchestrator / Stub tasks | `POST /v1/fanout` accepts `{ tasks: FanoutTask[], timeout_ms? }`, validates non-empty `tasks`, executes tasks concurrently with concurrency bounded by `Math.min(Math.max(1, fanout.max_parallel), tasks.length)`, resolves policy independently per task, isolates per-task errors/timeouts, and preserves input `tasks[]` order. | Empty/missing `tasks` returns HTTP `400`. Valid 3-task request returns HTTP `200` with `object === "mirevox.fanout_result"`, `parallel === Math.min(max_parallel, tasks.length)`, `results.length === tasks.length`, `results[i].id === tasks[i].id`, each entry containing `{ id, ok, decision, result|error, duration_ms }`. Per-task timeout produces `ok: false, error: "task timeout"` without failing sibling tasks. | `test/fanout.test.ts` ("runs tasks in parallel across backends") |
| **`FR-07`** | Key Vault — Storage & Precedence | Live | `KeyVault` persists entries in `{ version: 1, entries: [...] }` JSON at `config.vault.path` (mode `0o600`), initializes cleanly when the file does not exist, and resolves secrets via `SMART_ROUTER_KEY_<BACKEND_NORMALIZED_UPPER>` env override before file lookup. | `put()` writes file with mode `0o600` (`(stat.mode & 0o777) === 0o600`); `getSecret()` returns env value when set, else file secret, else `undefined`; `delete()` removes entry and returns `true` (or `false` if absent); missing file on boot creates zero errors. | `test/vault.test.ts` |
| **`FR-08`** | Key Vault — Admin CRUD & Redaction | Live | `GET /admin/keys`, `PUT /admin/keys/:id`, and `DELETE /admin/keys/:id` manage vault entries without ever returning raw secret values. | `PUT` missing `backend` or `secret` returns `400`; valid `PUT` returns `200` with `{ id, backend, updated_at, has_secret: true }` and `"secret" in body === false`; `GET /admin/keys` returns `{ data: [...] }` where `0` objects contain a `secret` key; `DELETE` returns `{ deleted: boolean }`. | `test/vault.test.ts` + `test/gateway.test.ts` ("stores vault keys") |
| **`FR-09`** | Registry — Discovery & Polling (Stub) | Live loop / Stub catalogs | `DiscoveryRegistry` tracks all configured providers (`foundry`, `bedrock`, `vertex`, `local`, `mcp`, `mock`), runs an initial `pollAll()` on `start()`, refreshes every `poll_interval_ms` (`30000 ms`, timer `.unref()`'d), and exposes `GET /admin/registry` and `POST /admin/registry/poll`. | Under `config/default.yaml`, `pollAll()` populates all 7 provider statuses with `healthy: true`, ISO-8601 `last_poll_at`, non-empty `models[]`, and `stub: true` (when `SMART_ROUTER_STUB_MODE` is true or no vault key is present). Disabled providers report `healthy: false, models: []`. | `test/gateway.test.ts` + `GET /admin/registry` + `POST /admin/registry/poll` |
| **`FR-10`** | Operations — Health, Banner & Config Overrides | Live | `loadConfig()` loads YAML from `SMART_ROUTER_CONFIG` (default `./config/default.yaml`), fails fast if missing, and applies env overrides (`SMART_ROUTER_HOST`, `SMART_ROUTER_PORT`, `SMART_ROUTER_API_KEY`, `SMART_ROUTER_VAULT_PATH`, `SMART_ROUTER_STUB_MODE`). `GET /` returns service metadata; `GET /health` returns `{ status: "ok", providers }`. `SIGINT`/`SIGTERM` stops the registry interval and closes the server. | Missing config path throws `Error("Config not found: ...")` and exits non-zero. Env vars override YAML values deterministically. `GET /health` returns `200` with `providers.length === 7`. | Startup check + Docker Compose healthcheck |

## 2. Non-Functional Requirements (v0.1 Locked)

| ID | Category | Requirement Statement | Measurable Exit Criterion | Verification Method |
| --- | --- | --- | --- | --- |
| **`NFR-01`** | Offline & Zero-Credential Operability | The complete build, typecheck, test suite, and Docker Compose runtime must operate with zero cloud credentials and zero outbound internet access. | `npm run typecheck`, `npm test`, `npm run build`, and `docker compose up --build -d` + `/health` + `/v1/models` + `/v1/chat/completions` + `/v1/fanout` all succeed with no `SMART_ROUTER_KEY_*` set and no live provider reachable. | Automated test run + clean Compose smoke test |
| **`NFR-02`** | Stub Latency & Concurrency | Gateway overhead and stub execution must remain fast and non-blocking; fan-out must execute independent tasks concurrently up to `max_parallel`. | `GET /health` responds in `< 50 ms`; single stub `POST /v1/chat/completions` responds in `< 100 ms` (simulated stub jitter is `5–24 ms`); a 3-task `POST /v1/fanout` finishes in `< 100 ms` with `parallel === 3`. | Test timing output (`test/gateway.test.ts`, `test/fanout.test.ts`) |
| **`NFR-03`** | Secret Isolation (v0.1 Baseline) | Stored vault secrets must never be serialized in HTTP API responses and must be persisted on disk with owner-only permissions. | `0` occurrences of stored canary secret strings across `GET /admin/keys`, `PUT /admin/keys/:id`, `GET /v1/models`, `GET /health`, `GET /admin/registry`, and `GET /admin/routes`; `vault.json` written with POSIX mode `0o600`. | `test/vault.test.ts` + `test/gateway.test.ts` |
| **`NFR-04`** | Stub Honesty & Determinism | Stubbed responses and catalog entries must be unambiguously marked so callers and downstream tools cannot mistake stubs for live model calls. | `100%` of stub completions contain `mirevox.stub === true` and content prefix `[mirevox-stub/<backend>]`; `100%` of stubbed models in `/v1/models` and `/admin/registry` carry `stub: true` when `SMART_ROUTER_STUB_MODE=true`. | Response schema assertions in `test/gateway.test.ts` |
| **`NFR-05`** | Type Safety & Build Hygiene | TypeScript strict mode (`strict: true`, `noUncheckedIndexedAccess: true`) must compile cleanly with zero warnings/errors. | `npm run typecheck` (`tsc -p tsconfig.json --noEmit`) and `npm run build` exit `0` with `0` diagnostics. | CI / local `npm run typecheck && npm run build` |
| **`NFR-06`** | Container Readiness & Footprint | Multi-stage Docker image (`node:22-alpine`) strips devDependencies (`npm prune --omit=dev`) and reaches healthy state quickly under Docker Compose. | `docker compose up --build -d` transitions `smart-router` to `healthy` (`GET http://127.0.0.1:18765/health` = `200`) within `<= 30 s` (`healthcheck` interval `10s`, timeout `3s`, retries `5`). | Docker Compose build & `docker inspect` health status |
| **`NFR-07`** | Modularity & Adapter Replaceability | Gateway routing, policy, vault, registry, fan-out, and backend execution remain cleanly decoupled behind TypeScript modules so live adapters (native SDKs, Ollama HTTP, or a downstream LiteLLM proxy) can swap in without breaking `/v1/*` or `/admin/*` contracts. | 7 distinct single-responsibility files under `src/` (`config`, `types`, `gateway/openai`, `router/policy`, `fanout/splitter`, `registry/providers`, `vault/key-vault`, `backends/stub`) with acyclic imports and zero direct `stubComplete` references outside `gateway/openai.ts` and `fanout/splitter.ts`. | Code inspection + `npm run typecheck` |
| **`NFR-08`** | Open-Source & Scope Hygiene | Repository uses Apache-2.0 licensing and excludes out-of-scope integrations. | `LICENSE` (Apache-2.0) exists at repo root; `package.json` declares `"license": "Apache-2.0"`; `0` runtime dependencies or config references to n8n, Instagram, or Sherali homelab. | Repo inspection |

## 3. Deferred v0.2 Hardening Requirements (Explicitly Out of v0.1 Exit Gates)

The items below were surfaced by `requirements-draft.md`, `market-gap.md`, and `devils-advocate.md`. They are **not claimed in v0.1** and serve as the mandatory exit gates before promoting Smart Router from a runnable stub to live-traffic use:

| Deferred ID | Target Capability | Planned Exit Criterion | Why Deferred Past v0.1 |
| --- | --- | --- | --- |
| **`H-01`** | Fail-closed `onprem` residency enforcement | Requesting a `cloud` backend/model under an `onprem`-pinned activity returns HTTP `403` (naming activity + placement) with `0` calls dispatched to cloud adapters, verified by hit-counter negative test. | `src/router/policy.ts` currently performs placement preference/nudge only; hard-deny enforcement requires backend-locality lookup inside `decide()`. |
| **`H-02`** | Fan-out timer cleanup & batch-size guard | Clear `setTimeout` handle in `fanoutTasks()` `finally` block so Node exits immediately (currently a 60s timer keeps the `npm test` process alive for ~60s); enforce `fanout.max_tasks` returning `400` above limit; reject duplicate `task.id`. | Identified during v0.1 verification; low-risk hardening fix for v0.2. |
| **`H-03`** | Separate client vs. admin bearer tokens (multi-profile auth) | Distinct gateway keys/profiles (e.g., VS Code vs. home chatbot vs. admin) so `/admin/*` cannot be called with a regular chat client key. | Single `SMART_ROUTER_API_KEY` is sufficient for single-operator v0.1 local stub. |
| **`H-04`** | Structured JSON egress log & canary scrubber | Emit 1 JSON log line per request/subtask (`timestamp`, `request_id`, `activity`, `backend`, `placement`, `model`, `status`, `latency_ms`, `usage`) with `0` prompt/response bodies and `0` canary secrets. | Composition contract for Mirevox `evals` and `data-lineage` modules once live traffic begins. |
| **`H-05`** | Zod runtime validation of YAML config & HTTP bodies | Validate `config/default.yaml` on startup and `/v1/*`, `/admin/*` JSON bodies using already-installed `zod` dependency; fail fast with field-level `400` / startup errors. | `zod` is in `package.json` but not yet wired in v0.1. |
| **`H-06`** | Live backend execution adapter (Ollama / LiteLLM / native SDKs) | Replace `stubComplete` behind a `CompletionBackend` interface; support at least one real local OpenAI-compatible runtime (Ollama) and optionally delegate cloud providers to LiteLLM/Bifrost or native SDKs with structured credentials (SigV4/ADC/Entra). | v0.1 proves control-plane contracts offline first. |
